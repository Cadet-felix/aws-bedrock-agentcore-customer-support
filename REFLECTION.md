# Project Reflection: Customer Support AI Agent

## 1. Key Design Decision
A core design decision was implementing a two-stage resilience pattern for the `calculate_loyalty_discount` tool and a non-intrusive `MemoryHook` architecture. Because financial and loyalty calculations require deterministic accuracy rather than LLM estimation, I delegated the discount arithmetic to the AgentCore Code Interpreter sandbox. Specifically, the script caps redeemable points at 50% of the order first (`min(loyalty_points, int(order_total * 0.50 * 100))`), floors that capped amount to a multiple of 500 (`(usable_points // 500) * 500`), applies sequential Gold/Platinum tier discounts, and unwraps `result["content"]` from the execution stream to return top-level JSON fields (`points_redeemed`, `tier_discount_pct`, `final_total`, `remaining_points`). To ensure high availability, I paired the sandbox execution with a local tier-discount fallback block inside the `try/except` handler so customers still receive a valid quote if the sandbox container is unavailable. Similarly, implementing long-term memory via Strands lifecycle hooks (`MessageAddedEvent` and `AfterInvocationEvent`) cleanly decoupled context retrieval and event persistence from tool-calling logic, automatically prepending `SEMANTIC` facts and `USER_PREFERENCE` entries across sessions without cluttering the raw prompt history.

## 2. Challenge Encountered and Solution
The most significant technical challenge occurred when integrating `AgentCoreBrowser` to fetch the live page title from `https://www.amazon.com`. First, running locally under Python 3.14 triggered a `RuntimeError: Timeout should be used inside a task` during thread teardown because `nest_asyncio` conflicted with Python 3.14's stricter `BaseEventLoop.shutdown_default_executor` timeout context check. Second, Amazon's heavy background scripts prevented Playwright's default `load` event from firing within the 30-second navigation window. I resolved both issues by patching `shutdown_default_executor` to safely clean up the executor on Python 3.14+ and configuring Playwright's `Page.goto` to use `wait_until="domcontentloaded"`, combined with explicit system prompt instructions to read `document.title`. This reduced browser execution to three fast tool calls with zero timeouts.

## 3. Extending the Agent for Production
To harden this agent for enterprise production, I would introduce Amazon Bedrock Guardrails to filter PII and block prompt injection attacks, replace IAM-only testing with Amazon Cognito OAuth2 JWT authentication at the AgentCore Gateway, and add dead-letter queues (DLQs) plus SNS PagerDuty notifications to the CloudWatch error alarm for automated incident response.
